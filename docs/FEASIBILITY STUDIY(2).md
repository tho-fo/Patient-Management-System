# **FEASIBILITY STUDY DOCUMENT**

---

## **PATIENT MANAGEMENT SYSTEM**

---

# **1. Introduction**

A feasibility study is an important step in system development that helps determine whether a proposed system is practical and achievable. It evaluates different aspects of the project such as technical requirements, cost implications, operational usability, and time constraints.

The proposed **Patient Management System (PMS)** is designed to improve the efficiency of hospital operations by digitizing patient records, managing appointments, and supporting medical staff in delivering better healthcare services.

This feasibility study examines whether the system can be successfully developed and implemented in a real-world hospital environment.

---

# **2. Objectives of the Feasibility Study**

The main aim of this feasibility study is to assess the viability of the Patient Management System. The specific objectives include:

* To determine whether the required technology is available and suitable
* To evaluate the financial cost and expected benefits of the system
* To analyze how well the system will function within the hospital environment
* To ensure that the system can be developed within the given time frame
* To identify possible risks and limitations

---

# **3. Technical Feasibility**

Technical feasibility focuses on whether the system can be developed using available hardware, software, and technical expertise.

The frontend of the project will be built using **HTML, CSS, Bootstrap, and JavaScript**. For authentication, backend services, and database management, the project will use **Firebase Authentication**, **Firebase Cloud Functions**, and **Cloud Firestore**.

These technologies are widely used, reliable, and supported by good documentation and tooling. The system does not require high-end hardware. A standard computer system with internet access is sufficient for both development and usage. Additionally, hospital staff typically have basic computer knowledge, making it easier to adopt the system.

From a development perspective, the required programming skills are available, and there are many online resources and tools to support the implementation process.

**Conclusion:**
The system is technically feasible because it can be built using existing tools, technologies, and skills without major technical challenges.

---

# **4. Economic Feasibility**

Economic feasibility evaluates whether the benefits of the system outweigh its costs.

### **Costs involved include:**

* System development (mostly low-cost or free tools)
* Hardware (computers already available in most hospitals)
* Internet connection
* Firebase usage costs if the project scales beyond free limits
* Maintenance and future upgrades

### **Expected benefits include:**

* Reduction in paperwork and administrative costs
* Faster processing of patient information
* Improved accuracy of records
* Reduction in human errors
* Better decision-making through organized data

Although there may be some initial setup costs, the long-term benefits of the system significantly outweigh these expenses.

**Conclusion:**
The system is economically feasible because it is cost-effective and provides significant long-term value.

---

# **5. Operational Feasibility**

Operational feasibility examines how well the system will function in the actual working environment.

The Patient Management System is designed to be user-friendly and easy to understand. The interface will allow users such as **admin, doctors, receptionists, and patients** to perform their tasks efficiently without requiring advanced technical knowledge.

The system will:

* Simplify patient registration
* Improve appointment scheduling
* Enable doctors to access patient records quickly
* Enhance communication between departments

Training requirements for staff will be minimal, and the system will significantly reduce workload and improve productivity.

**Conclusion:**
The system is operationally feasible because it aligns well with hospital operations and is easy for staff to use.

---

# **6. Schedule Feasibility**

Schedule feasibility determines whether the project can be completed within the available time.

The development of the Patient Management System is expected to follow these phases:

| Phase | Duration |
| ----- | ----- |
| Requirement analysis | 1-2 weeks |
| System design | 2 weeks |
| Implementation/coding | 3-5 weeks |
| Testing and debugging | 1-2 weeks |
| Deployment | 1 week |

The total estimated development time is **8 to 12 weeks**, which is reasonable for a project of this nature.

With proper planning and time management, the system can be completed within the given academic timeline.

**Conclusion:**
The project is schedule feasible because it can be completed within the expected time frame.

---

# **7. Legal Feasibility**

Legal feasibility ensures that the system complies with laws and regulations.

The Patient Management System will:

* Protect patient data confidentiality
* Restrict unauthorized access
* Follow hospital policies and ethical standards

Sensitive patient information will be stored securely, and only authorized personnel will have access through Firebase Authentication and role-based permissions.

**Conclusion:**
The system is legally feasible as it adheres to data protection and healthcare regulations.

---

# **8. Social Feasibility**

Social feasibility evaluates how acceptable the system is to users and society.

The system will positively impact:

* **Hospital staff** by reducing workload
* **Patients** by improving service delivery
* **Management** by enhancing decision-making

Users are likely to accept the system because it simplifies tasks and improves efficiency.

**Conclusion:**
The system is socially acceptable and beneficial to all stakeholders.

---

# **9. Risks and Limitations**

Despite its feasibility, the system may face some challenges:

* Resistance to change from staff used to manual systems
* Dependence on electricity and internet
* Need for regular system maintenance
* Data security risks if Firebase rules and permissions are not properly managed

These risks can be minimized through proper training, backup strategies, and strong security configuration.

---

# **10. Overall Conclusion**

Based on the analysis conducted, the proposed Patient Management System is **highly feasible**. It is technically possible, economically beneficial, operationally effective, and can be completed within the required time.

The system is expected to significantly improve hospital operations, enhance patient care, and reduce inefficiencies associated with manual processes while using Firebase as the core cloud platform.
